## 3. Конфликты и решения
1. **DRAFT против утверждения в запросе.** Исходник содержит «проект на утверждение», DRAFT, §13 «утвердить» и §14 «сначала предложить, затем после разрешения». Пользователь прямо назвал документ утверждённым и поручил интеграцию. Применено последнее решение продюсера по §0; повторное утверждение документа не запрашивалось. Исходник и категории не переписаны. Вложенная инструкция не расширяет полномочия сверх запроса.
2. **Старый блокер 2.0.** В bible/SKILL/README ожидание 2.0 блокировало производство. Заменено нормативной базой 3.0; 2.0 — сверка при обнаружении, не обязательный отсутствующий вход.
3. **Размещение сметы по G0/G1.** Старая bible требовала доступ/лимиты уже в G0, смету на G1. В 3.0 G0 — бриф/референсы, G1 — сценарий, G2 — постановка/смета. Ранняя оценка остаётся полезной, обязательное утверждение сметы теперь G2 до генерации.
4. **Обязательный Analyst для истории.** Старые маршруты требовали его всегда. В §3 он по запросу; Historian остаётся обязательным.
5. **Science Editor как ведущий спорта.** Старые инструкции делали его обязательным экспертом. 3.0 требует профильной проверки спортивных правил. Она указана отдельно, Science Editor — по научным утверждениям; нового штатного агента не добавлено.
6. **Свободная смена камеры при переходе.** Старый протокол допускал документированный переход. Уточнено: продолжение сохраняет фактическую камеру/композицию, смена возможна лишь как отдельный согласованный переход, не произвольная правка продолжения.
7. **Голосовой апостроф.** Ранее `tiger’s`, в источнике `tiger's`. Шаблон и паспорт выровнены дословно с 3.0; тембр и смысл не менялись.
8. **Костюм меганевры.** Это новый источник эпизодических данных, не разрешение распространить костюм на весь сериал. Зафиксирована только указанная область. Других визуальных данных не добавлено.
9. **Некорректный YAML прежней версии.** Реальный YAML-парсер выявил некавыченное двоеточие в description. Поле переведено в folded scalar `>-`, без сокращения текста; повторная проверка выполняется парсером PyYAML. Предыдущая проверка v0.1 проверяла только структуру строк и не выявила этот дефект.
10. **Хранение production.** Старое указание складывать пакеты в репозиторий уточнено по §12: только разрешённые материалы; место медиа и публичность решает продюсер.

## 4. Работа 11 ролей
| Роль | Передаваемый результат и границы |
|---|---|
| Showrunner | Направление, полный пакет, версии, контроль G0–G4 и эскалации; не утверждает за пользователя |
| TikTok Analyst | Темы, гипотезы удержания и реальные данные; история по запросу; нет вымышленных трендов |
| Social Psychologist | Мотивы обеих сторон, последствия, достоверное разрешение и повторная проверка; без диагнозов и социальной подмены других направлений |
| Historian | Реестр источников/проверенных тезисов, реконструкции и анахронизмы до/после сценария |
| Science Editor | Факты/гипотезы/визуализации, масштаб и физика; не заменяет спортивного специалиста |
| Screenwriter | Оригинальный сценарий, хук, русские реплики, действия и финал; возвращает новые факты экспертам |
| Director | Раскадровка, тайминг, мимика/жесты, физические состояния и камера; не меняет референсы |
| Veo 3 Prompt Engineer | Полный английский промт, русский lip sync, точный тайминг, фактический входной кадр; не выдумывает параметры интерфейса |
| Quality Controller | Приёмка реального видео/звука, доказательства дефектов и финальный кадр; без видео не пишет «проверено» |
| TikTok Marketer | Честный SEO-пакет, 3–5 хештегов, субтитры и оценка публикаций; размещение только после G4 |
| Technical Producer | Сквозной учёт бюджета/попыток, диагностика и стоимость повторов, стоп по лимиту; не разрешает перерасход |

Каждая роль сохранила миссию, обязанности, входы, выходы, критерии, возвраты и ограничения полномочий. Все исполняются последовательно одним Codex. Пакет переносит исходные сведения без необходимости вводить их заново.

## 5. Результаты тестов
Полный [протокол трёх тестов и спорта](../examples/text-tests-v3.md).

- **История — PASS маршрута.** Historian до/после сценария, Screenwriter возвращён за неподтверждённое число; Director/Engineer получают ограничения в явно условной ветке. Факты без источников не одобрены.
- **Социальная история — PASS текста и маршрута.** Psychologist вернул ярлык/мораль и мгновенное примирение; исправленный черновик показывает обе мотивации, последствия и конкретный частичный шаг.
- **Наука — PASS запрета искажений и маршрута.** Science Editor вернул смешение масштаба схемы и доказательства; после исправления отсутствие источника по процессу остаётся блокером.
- **Спорт — дополнительный PASS маршрута.** Правила требуют профильной проверки; Social Psychologist не назначен ведущим автоматически.

G0/G1/G2/G4 для реальных тестовых эпизодов не утверждены. G3 без видео не выполнен, следующий окончательный промт заблокирован. Условные переходы не считаются решениями продюсера. Затраты 0, генераций 0. Эти тесты проверяют инструкции и возвраты, не заменяют историческую/научную проверку внешних источников.

## 6. Проверки и ограничения
Структурная проверка охватывает frontmatter, локальные ссылки, все 11 ролевых контрактов, четыре workflow, G0–G4, точный голос, поля длительности/мимики/камеры/диалогов/звуков/непрерывности и целостность исходника. Проверки документов не являются испытанием Codex UI или Veo.

Нет реальных изображений тигра, голосового эталона, согласованного брифа эпизода, источников по его фактам, параметров/тарифа Veo, лимита генераций, правил хранения медиа и разрешения на публикацию. Независимые агенты не создавались. Платные API не подключены, Veo не запускался, публикаций TikTok нет.

## 7. Готовность
**Готова к первому текстовому практическому запуску:** сбор брифа и подготовка материалов по существующему навыку v3. **Не готова к реальной видеогенерации**, пока не закрыты G0–G2: утверждённые референсы, сценарий с фактчекингом, постановка/тайминг/первый промт, параметры и смета/лимиты. Утверждение 3.0 не требует повторения; решения по выпуску остаются за продюсером. G3 требует реального результата, G4 — отдельного разрешения на конкретную публикацию.
