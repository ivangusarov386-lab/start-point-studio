# Единый протокол передачи

Использовать [шаблон пакета](../templates/production-packet.md) для всех ролей. Пакет передаётся целиком либо как версия с точными ссылками на доступные артефакты; фраза «как обсуждали» недостаточна. Не удалять ограничения предыдущих ролей. Хранение: `production/<episode-id>/` для разрешённых к хранению текстовых пакетов при запросе на выпуск. Место хранения медиа и допустимость публичных материалов утверждает продюсер; закрытые медиа, персональные данные и секреты не добавлять в Git. Текущий навык не создаёт производство автоматически.

## Статусы
- APPROVED: указанная роль проверила конкретную версию на данном этапе; все обязательные условия этапа выполнены.
- REVISION_REQUIRED: есть дефект; обязательны ID, доказательство (кадр/реплика/источник), приоритет, серьёзность, адресат, требуемое исправление и критерий повторной проверки.
- WAITING_FOR_PRODUCER: отсутствует обязательное решение или материал продюсера; зависимая работа остановлена, независимая текстовая подготовка допустима с TODO.

Различать статус отдельных артефактов и пакета. Пакет APPROVED только если текущие обязательные проверки APPROVED и необходимые решения продюсера присутствуют. При дефекте ставить REVISION_REQUIRED; после исправления при оставшемся решении — WAITING_FOR_PRODUCER. Не использовать APPROVED для всего выпуска по результатам одного шага.

## Передача и возврат
Автор указывает отправителя, получателя, этап, версии входов/выходов, ограничения и следующий шаг. Получатель проверяет наличие входов и полномочий до работы. Изменение утверждённого артефакта аннулирует зависимые проверки: перечислить затронутые материалы и повторить проверки, включая продюсера при изменении его решения.

## План и наблюдение
Запланированный финальный кадр находится в раскадровке. Фактический — только в QA после просмотра конкретного файла. Запись включает ID клипа/попытки, путь и версию, длительность, таймкод последнего декодируемого кадра, изображение кадра или доступную ссылку, описание состояния и отклонений, прослушанный звук. Если видео недоступно, не выдумывать наблюдения: QA не пройден, следующая генерация заблокирована.

Следующий промт ссылается на принятый клип и фактический кадр, описывает совпадающее начальное состояние. При продолжении сохранять положение камеры, угол, перспективу и кадрирование. Смена плана/места возможна только как отдельный явно согласованный Director переход с документированными сохраняемыми признаками. Поддержку image/reference/extend проверять отдельно; текстовое описание кадра не выдавать за его техническую передачу модели.

## Дополнения v3 (§7–10, §12)
Showrunner проверяет каждый переход, Technical Producer обновляет стоимость и число попыток на всём маршруте. Пакет включает результат роли и утверждённый бриф; следующая роль использует эти данные без просьбы повторить исходное сообщение. Для существенного отсутствующего поля запросить только его.

При получении финального скриншота проверить, к какому клипу и попытке он относится; если принадлежность неясна, запросить уточнение и не подставлять кадр в продолжение. Записать источник/версию изображения и реально видимые состояния: хват, положение предметов, взгляд, свет, камера/перспектива/кадрирование. Изображение важнее плана, но не подтверждает звук и не заменяет QA всего видео. Не домысливать невидимые действия. При недоступном видео G3 не выполнен: запрос результата у продюсера имеет WAITING_FOR_PRODUCER, дефекты текста/видимого кадра отдельно REVISION_REQUIRED.

Повтор допускается только с диагнозом, новой версией промта и оценкой пользы/затрат в пределах утверждённых лимитов. Без лимита/тарифа — ожидание решения. Исходные версии сохранять; при изменении сцен обновлять зависимые промты и проверки. В текстовых тестах отдельно обозначать условные входы/переходы; они не входят в реальные решения G0–G4.
